# 俯视漂移实车安全联锁验收 runbook（P1，2026-10-12）

> 依据：`docs/plan/overhead-drift-test-plan.md` §4.3/§5/§6（遗留评估项固化）、
> `web_ui/backend/drift_session.py`（接管判据 RFC 7.2）、
> `web_ui/backend/drift_controller.py`（radius_freq_sign RFC §7.3）。
> 可执行工具：`scripts/safety_acceptance.py`（清单记录 + 两条判定规则）。
> 使用方式：**按序执行，每项记录数字**；失败只记录现象与数据带回分析，
> **勿现场改代码**。

## 0. 目的与范围

把夜间加固后的安全链路在实车上做一次完整验收，并把两条此前"带回分析"
的决策点（半径环符号、低速 β 噪声 vs 接管判据）用实测数据当场判定。
验收对象是**安全联锁本身**，不是控制性能：性能验收走
`docs/plan/overhead-drift-test-plan.md` 的 M0~M5。

通过标准：清单 R1~R8 全部 pass，且 D1/D2 判定成立（或按建议闭环）。
任何 fail → 停止进入实车漂移环节，带回分析。

## 1. 安全模型（三层兜底，验收即验证这三层）

1. **RC 夺回**：任意 AUTO 状态拨 RC MODE 0 立即人工接管（第一兜底，
   全程有效）；
2. **看门狗**：ENGAGED 期逐帧巡检（检测丢失 >0.2s / 遥测停滞 >0.5s /
   下发连续失败 ≥3 次）→ car_mode→0 + 零油门，原因记入 events；
3. **非 AUTO 不动车**：观察期/IDLE 只记事件、绝不下发转向/油门
   （车在人手里）。

接管判据（`drift_session.py`）：观察期 `|β| ≥ 15°` **持续 500ms 且零次
跌破**才切入 ENGAGED；任一样本跌破阈值或丢检测帧都清计时。这是 D2
评估的对象。

## 2. 前置条件（顺序必做）

1. 测试计划 §0.1 清场启动 + §0.2 相机冒烟通过（含 WebRTC 路径、
   `camera_loop_errors=0`）；
2. M0 延迟实测达标（端到端 P95 < 100ms，丢帧率 < 5%）；
3. `GET /api/drift/state` 可达，`config` 快照保存（参数漂移可回溯）；
4. RC 遥控器电量充足、急停通道现场验证一次（拔电池/急停开关，按现场
   硬件形态）；
5. 清场：圆心附近无人无物，安全员就位（第一兜底是人，不是软件）。

## 3. 验收步骤（对应 `checklist` 子命令 R1~R8）

执行：`python scripts/safety_acceptance.py checklist --server http://127.0.0.1:8000 --out safety_record.json`
（后端对外监听时追加 `--token <令牌>`；取证会拉 `events` 尾部与
`send_failures`/`camera_loop_errors` 计数。）

| # | 项 | 操作 | 预期 | 注意 |
|---|----|------|------|------|
| R1 | 看门狗-检测丢失 | ENGAGED 中遮住镜头 >0.2s | car_mode→0 + 零油门；events `kind=watchdog`、`reason=检测丢失超时` | 仅 ENGAGED 触发 |
| R2 | 看门狗-遥测停滞 | ENGAGED 中断开车端连接 >0.5s | 同上，`reason=遥测停滞超时` | 仅 ENGAGED 触发 |
| R3 | 看门狗-下发失败 | ws 异常期间观察 `send_failures` | ≥3 次 → `reason=控制下发连续失败` | 通常与 R2 同源，不强求单独隔离 |
| R4 | 非 AUTO 不动车 | IDLE/观察期遮镜头、断遥测 | **只记事件、绝不动车** | 设计行为 |
| R5 | MODE 0→2 跳变 | 接管/退出瞬间肉眼观察 | 平滑无抽搐/窜动；异常记录现象 | 贯穿低速闭环与定圆阶段 |
| R6 | 多 client 仲裁 | AUTO 期间开第二个标签键盘控车 | 控制被服务端丢弃、回发 `control_rejected`、车不受干扰 | 含同标签页 |
| R7 | RC 夺回 | 任意 AUTO 状态拨 MODE 0 | 立即人工接管 | 第一兜底，全程有效 |
| R8 | M5 定圆保持 | β*≈25° 起漂后定圆保持 30s | β 均值误差 < 5°，半径波动可接受 | 真实漂移段是看门狗/护栏的最终考场 |

R1/R2 触发后恢复：排除触发原因 → 重新点「自动漂移」即可，无需重启后端。

## 4. 判定规则

### D1 半径环符号实证（radius_freq_sign，M2 后执行）

背景：`radius_freq_sign` 默认 **-1**（RFC §7.3 机理负反馈假设：
「频率高→半径小」，偏内→降频→扩半径）。若实测机理相反，须置 **+1**。

执行：

```bash
python scripts/safety_acceptance.py radius-sign data/drift_tubs/overhead_<时间戳> --center 0.5,0.5
```

判定（阈值 |r| ≥ 0.6，与 `throttle_analysis.correlate` 同口径）：

| 频率↔半径 Pearson r | 判定 | 动作 |
|---------------------|------|------|
| r ≤ -0.6 | 机理成立 | `radius_freq_sign` 保持 -1，不改 |
| r ≥ +0.6 | 机理反转 | 按脚本打印的载荷 `POST /api/drift/config {"radius_freq_sign": 1}`（热改生效） |
| 其余 | 证据不足 | **停下修正机理模型**（查圆心参数/滑窗特征/录制是否含漂移段），勿带病整定控制器 |

### D2 低速 β 噪声 vs 接管判据（M4 低速闭环后执行）

背景：0.2s 割线基线下低速段 β 抖动水位 ≈6.5~8°，而现行接管判据要求
500ms **零次跌破**——真实超阈若夹杂噪声回落，计时反复清零，可能出现
「β 已超阈但迟迟不接管」。

执行：M4 参数（β\*=0、脉冲频率 0、基础油门 0.2）低速闭环跑圈，
把该段 tub（或导出 `t_s,beta_deg` CSV）喂给：

```bash
python scripts/safety_acceptance.py beta-noise --tub data/drift_tubs/overhead_<时间戳>
```

脚本在同一批数据上回放三种判据（阈值 15°、保持 500ms，缺口 >0.2s 清
计时——与 `drift_session.py` 逐条对齐）：

| 判据 | 语义 | 状态 |
|------|------|------|
| `zero_dip` | \|β\|≥15° 持续 500ms 且零次跌破 | 现行实现 |
| `window_mean` | 滑窗（默认 500ms）均值 \|β\|≥15° 持续 500ms | 备选 |
| `over_ratio` | 滑窗内超阈样本占比 ≥0.8 持续 500ms | 备选 |

判定输出：

- **pass**：现行判据接管延迟 ≤1s → 判据不动，记录水位数字；
- **criterion_mismatch**：数据有持续超阈段（滑窗均值 ≥2s 超阈）但现行
  判据未接管/延迟 >2s，而备选判据更快 → 按建议改判据（列入判据修订
  议题），**勿现场改代码**；
- **no_data**：数据不含持续超阈段 → 仅记录噪声水位，补一段真实超阈
  数据再评。

无论结果如何，把噪声水位（均值/σ/峰峰值）与三判据接管延迟记入 §6
记录表——这是 M4 正式评估的输入。

## 5. 记录与存档

每项记录：**时间 / 参数快照（config）/ 结果数据（数字！）/ 现象描述 /
结论 ✅❌**。清单结果由 `checklist --out` 自动落 JSON，判定规则输出
粘贴进同一份记录。全部原始记录按测试计划 §9 模板补进交接文档对应 §。

## 6. 失败处置与升级

- 任何 fail / 判据不适配：**不现场改代码**，记录现象 + 数据 + config
  快照带回分析；
- 看门狗误触发（非预期条件触发）按缺陷处理，记录触发条件与 events
  尾部；
- RC 夺回失效（R7 fail）为**阻断级**缺陷：立即终止全部实车测试；
- 异常速查（黑屏/丢检测/WebRTC 回退等）见测试计划 §7。
