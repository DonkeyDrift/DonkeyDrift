## 4. M4 低速闭环（第 4 步，先非漂移！安全第一）

1. 参数：β\*=0、脉冲频率 0（连续油门）、基础油门 0.2
2. 点**自动漂移** → 状态变「自动·观察」→ 低速 RC 遥控进圆，验证转向闭环方向、车能跟圆
3. **低速 β 噪声 vs 接管判据**（遗留评估项，本次收数据）：0.2s 割线基线下低速段 β 抖动水位 ≈6.5~8°，接管判据要求 500ms 零次跌破阈值，低速段可能接管困难。
   - 现象若复现（β 已超阈但迟迟不接管）：记录 β 曲线/水位数字带回，后续判据改滑窗均值或超阈占比——**勿现场改代码**
4. 安全联锁同步核对：RC 遥控器随时可夺回（MODE 0）；接管瞬间观察 **MODE 0→2 跳变**是否平滑（抽搐/窜动则记录）

## 6. 安全链路专项核对清单（夜间加固的实车验证）

观察途径统一为 `GET /api/drift/state` 的 `events` 数组（尾部 20 条，`kind`/`detail`/`t_s`）与车本身的行为。

| # | 项 | 操作 | 预期 | 触发条件注意 |
|---|----|------|------|--------------|
| 1 | 看门狗-检测丢失 | ENGAGED 中遮住镜头 >0.2s | car_mode→0 + 零油门；events 出现 `kind=watchdog`、`reason="检测丢失超时"` | 仅 ENGAGED 触发 |
| 2 | 看门狗-遥测停滞 | ENGAGED 中断开车端连接（SBC 断网/杀 manage.py）>0.5s | 同上，`reason="遥测停滞超时"` | 仅 ENGAGED 触发 |
| 3 | 看门狗-下发失败 | ws 异常期间观察 `send_failures` 计数 | ≥3 次 → `reason="控制下发连续失败"`；通常与 #2 同源，不强求单独隔离 | 仅 ENGAGED 触发 |
| 4 | 非 AUTO 不动车 | IDLE/观察期遮镜头、断遥测 | **只记事件、绝不动车**（昨夜修正的语义） | 设计行为 |
| 5 | MODE 0→2 跳变 | 接管/退出瞬间肉眼观察 | 平滑无窜动；异常记录 | 贯穿 4/5 步 |
| 6 | 多 client 仲裁 | AUTO 期间开**第二个浏览器标签**尝试键盘控车 | 控制被服务端丢弃、回发 `control_rejected`、车不受干扰 | 含同标签页 |
| 7 | RC 夺回 | 任意 AUTO 状态拨 RC MODE 0 | 立即人工接管 | 全程有效，第一兜底 |

## 7. 异常处置速查

- **黑屏/预览不出** → 先 `tasklist | grep -i python` 查残留，按 §0.1 清场流程重启（残骸持相机句柄是历史事故根因）
- **快推丢检测** → 确认曝光已压 -8/-9；自动曝光下运动模糊必丢检测，任何算法参数无解
- **预览卡 ≠ 处理掉帧** → 五链路法：先看 state 里 `camera_fps`/`read_ms`/`detect_ms` 再定位
- **WebRTC 回退 MJPEG** → 首轨超时回退是设计行为；发生了就记录 console 日志带回
- **看门狗触发后** → 排除触发原因 → 重新点「自动漂移」即可，无需重启后端
- **改后端代码后** → 必须整体重启（热重载会被相机线程卡住，不可信）
