# AIMO 量化校准的坑：单侧校准会把输出头「截死」

> 实测于 DKG-1（DonkeyCar 行为克隆模型，输出 steering/throttle 两个 `[1,1]` 标量）
> → QCS6490 / QNN 2.40 / aidlite 2.5.1.304。

## 现象

NPU 模型（INT8 与 INT16 都一样）在真实车帧上**某个输出头恒为 0.000000**，
而 float32 参考模型在同一批帧上给出正常数值：

| 测试集 | float32 参考 | NPU（校准=tub 真实帧） |
|---|---|---|
| 21 帧去重真实帧 | steering **−0.159 ~ −0.338**（21 个不同值） | steering **全 0**（21/21）✗ |

先怀疑"测试帧选得不好"，所以做了去重（787 帧里仅 272 帧唯一）并按转角均匀抽样 —— **仍是全 0**。

## 定位：用合成输入探响应

用黑/白/灰/左右分块/上下分块等合成图（能强制把输出推到两个符号）逐头看：

| 合成输入 | float32 参考 steer / throt | NPU(INT16) |
|---|---|---|
| 全黑 | +0.084 / +0.463 | +0.085 ✓ / **0.000** ✗ |
| 全白 | +0.225 / +0.420 | +0.225 ✓ / **0.000** ✗ |
| 左黑右白 | +0.204 / +0.596 | +0.202 ✓ / **0.000** ✗ |
| 左白右黑 | +0.374 / −0.187 | +0.373 ✓ / −0.190 ✓ |
| 上黑下白 | **−0.099** / −0.929 | **0.000** ✗ / −0.930 ✓ |

规律：**steering 头只保留正值（负→0），throttle 头只保留负值（正→0）**。
再读**原始整型**张量（`get_output_tensor(i, DataType.TYPE_INT16, False)`）确认值为 0 →
不是索引/读取问题，是量化后该张量真的输出零点。

## 根因

AIMO 按**校准集数据的激活范围**给每个张量定 min/max。
只喂 tub 真实帧时，那份数据的参考输出恰好是**单侧**的（steering 全负、throttle 多为负）⇒
输出张量被标成单侧范围 ⇒ 落在范围之外（即反号）的值被压到零点，读出来恒 0。

一句话：**校准集的输出分布有多单侧，量化后的输出头就有多"半死"。**

## 修复：校准集必须覆盖输出双侧

`donkeycar/tools/aimo_npu_convert.py` 新增 `--calib-mix-synth N`（建议 ≥30）：
在校准集里混入 `black / white / gray / 左右分块 / 上下分块 / 渐变 / 噪声` 合成图，
把输出范围拉回双侧。合成图与真实帧按 `N : (max-N)` 混合。

```bash
.venv/bin/python -m donkeycar.tools.aimo_npu_convert \
    --onnx models/DKG-1.tflite --out ~/models/out_INT16 \
    --precision INT16 \
    --calib-tubs /path/to/tub --calib-max 100 --calib-mix-synth 40
```

实测（21 帧去重真实图 vs float32 参考）：

| 模型 | steering 平均\|Δ\| / 最大\|Δ\| | throttle 平均\|Δ\| / 最大\|Δ\| |
|---|---|---|---|
| INT8（仅 tub 校准） | 0.2307 / 0.3384（非零 **0/21**）✗ | 0.0235 / 0.0559 |
| INT16（仅 tub 校准） | 0.2307 / 0.3384（非零 **0/21**）✗ | 0.0017 / 0.0043 |
| **INT16（+40 张合成图）** | **0.0031 / 0.0058（非零 21/21）** ✓ | **0.0020 / 0.0036（非零 21/21）** ✓ |

推理耗时不变：**0.84 ms/次**（50 次平均）。

## 判据与预防（下次怎么快速认出这个坑）

1. **症状**：某个输出头在**同一符号区间**内读数恒 0，另一符号区间正常 →
   立刻怀疑"单侧校准"，别去改前处理/索引。
2. **三步判据**：
   - 读**原始整型**张量，若为 0（且该头参考值明显非 0）→ 是量化范围问题，不是读取问题；
   - 用**合成图**（黑/白/块状）分别推两个符号区间，看哪一侧死；
   - 换一版**混入合成图**的校准集重转，若死的那侧活了 → 确认。
3. **预防**：任何回归/连续输出模型（控制类、标量输出）**一律**在校准集里放能产生反号输出的样本；
   真实数据往往天然单侧（这辆车的 steering 就一直偏一侧）。
4. 顺带：`INT16`（`A16_W8`）在同样的耗时下精度显著优于 `INT8`（throttle 平均|Δ| 0.0235 → 0.0017），
   小回归模型优先用它。
