# 模拟器断流恢复最小修复

状态：规范已获确认，最小修复及自动化故障注入验证完成。

## 证据与范围

现场 WebRTC 保持连接但帧源停止。真实 `observe()` 在断连后仍无限等待，
后台替换环境对象不能释放困在旧对象上的采集线程。
本修复解决该恢复缺陷，不声称已经确定首次模拟器遥测停止的原因。
保留 90 kHz 时间戳、编码器、相机参数及 WebRTC 协议，不修改 Unity。

仅修改 `gym-donkeycar` 的 TCP 关闭、观测等待和相关真实遥测状态，
以及 `DonkeyDrift` 的环境切换及恢复健康判定；补充直接相关回归测试。
不采用反复重启整个车端或隐藏异常的方案。

## 客户端生命周期

- TCP 接收 EOF、RST、异常退出和显式 stop 均使连接健康状态变为 false。
- stop 先关闭 socket 唤醒 I/O，再有限时等待接收线程；禁止线程 join 自己。
- 接收回调通知 aborted 时允许安全调用 stop；关闭操作可重复。
- observe 等待期间检查连接状态及单调钟期限，断连抛 ConnectionError，
  无新帧超时抛 TimeoutError，不返回旧图或合成空图冒充恢复。
- 异步默认观测等待期限 5 秒，可用客户端配置 observe_timeout 调整。
  同步训练仍为有限等待，可显式放宽期限，不改变同步动作/观测配对。
- 场景加载等待也遵守有限期限和断连状态，避免重建线程卡在握手。

## 恢复与真实遥测

- 为 handler 单独记录最近实际收到的遥测时刻，初始化和 reset 不刷新该值。
  保留原 time_received 作为旧观测配对接口，避免无关协议改动。
- DonkeyGymEnv 健康检查优先使用真实遥测时刻；TCP 握手和 reset 占位图
  不算已恢复。兼容旧客户端时退回原遥测接口。
- 创建环境并 reset 成功前不向 update 线程发布新环境对象。
  reset 失败关闭待发布环境，清空连接状态，不遗留 socket。
- update 处理旧 step 的异常和返回结果时检查对象身份，避免关闭新环境
  或将旧图混入新连接的帧流。关闭时先摘除旧环境，使旧线程不能继续拿到它。
- 确认收到真实观测后才发布“连接恢复成功”。后台重建仍不阻塞车辆主循环。
- 既有看门狗周期和重连合并机制保留；不增加新的重复重建策略。

## 验收

1. 已断连、EOF、RST及从接收线程 stop 均收敛，无 self-join 异常或遗留线程。
2. 健康但不发帧的连接，observe 在期限内失败；正常新帧及时返回。
3. 初始化/reset 合成时刻不能被健康检测当作真实遥测。
4. 真实 socket 和真实 gym 包装链下，至少连续三次模拟断流后恢复；
   验证遥测持续前进、采集线程活着、预览 sink 持续收到帧、旧 socket 关闭。
5. 新连接只有配置握手但没有真实遥测时不能报告恢复成功，并能再次重试。
6. 同时运行既有断连、桥接、90 kHz 轨道和编码器回归。

故障注入使用独立临时端口的假模拟器，不接管用户当前的模拟器或浏览器。
不自动重启或强杀现有进程；本地真实长时间驾驶需车端重新加载代码后验证。
测试通过不等于首次停流原因已查清，未验证项单独说明。

不提交 Git，除非用户明确授权。保护当前未提交的时间戳改动。

## 实施与验证记录

- 修复前新增测试复现四项失败：断连/关闭不能退出 observe、
  活连接无帧永久等待、reset 失败不关闭候选环境。
- 客户端 stop 先唤醒并关闭 socket，再有限时等待其他线程，
  EOF/RST 收敛为断连状态；连接建立失败也关闭 socket。
- observe 和场景加载采用单调钟有限等待；正常 1 ms 轮询保留。
- handler 新增 `last_telemetry_ts`，初始化为 0，只在实际图像遥测接收时更新。
- 环境完成 reset 和真实遥测检查后才发布；失败候选环境及时关闭。
  旧 step 返回/异常通过重连锁及对象身份检查隔离。
- 主仓库定向回归 145 项通过，覆盖原 90 kHz 轨道、桥接、编码器、
  模拟器预览、恢复模板及新增断流恢复。客户端基础测试另 1 项通过。
- 独立假模拟器真实 TCP 注入：三次 RST、三次保持 TCP 的遥测静默、
  三次静默后重连仍只有握手，再次重试恢复；均验证预览 sink 持续出帧、
  原采集线程继续运行及旧 socket/接收线程释放。
- 故障注入测试关闭假模拟器的进程启动等待（`start_delay=0`），
  不修改用户实际模拟器的启动配置。Windows RST 测试使用本平台 linger 结构。
- 验证期间没有连接真实模拟器、重启车端、强杀进程或接管浏览器会话。

本次结论限于恢复缺陷。实际 Unity 首次停流的原因和重新加载代码后的
长时间驾驶稳定性尚未验证。停车后正常重新启动车端即可加载两个仓库的修复，
无需重新安装依赖或重新构建 Unity。代码和本规范均未提交 Git。
