让「手柄」兼容更多设备——转向轴可配置 + 中位可校准

当前实现的转向被硬编码在左摇杆 X 轴（axes[0]），而你的手柄左右是 Z 轴，所以前后油门正常、左右失效或反向。本页是给评估用的设计参考：第 1 节是可真实连接手柄的调试台，第 2 节给出 A / B / C 三套界面方案，第 3 节是落地细节。

问题：转向轴硬编码 axes[0] 目标：轴可配 / 可反向 / 死区可调 / 可校准 待你筛选：界面形态 A / B / C

0 问题定位

现象：切到手柄后，前后油门正确，左右转向不生效或方向相反。根因是输入映射写死了轴序号。

现状（useGamepadDrive.ts）

// 写死：左摇杆横向 = 转向，纵向 = 油门
const x = applyDeadzone(pad.axes[0]);
const y = applyDeadzone(pad.axes[1]);

const angle    = clamp(x);
const throttle = clamp(-y * maxThrottle);

你的手柄（推断）

// 转向在 Z 轴，约 axes[2]；油门仍在 Y 轴
angle    = f(pad.axes[2]);   // Z 轴，可反向
throttle = clamp(-pad.axes[1] * maxThrottle);

// Z 中位 = 直行；两侧极值 = 左 / 右满舵
// 具体极性以「实时调试台」实测为准，勾反向即可
硬编码 axes[0] → 配置化的 轴 / 反向 / 死区 / 上限 → 预设 + 一键校准向导，兼容通用手柄

方案 A · 抽屉内嵌「手柄设置」折叠卡

在现有「虚拟摇杆」抽屉里、控制参数上方，新增一张可折叠卡片。选中「手柄」输入源时自动展开，平时收起。

  • 与现有 控制参数 面板同构，学习成本最低、改动最小
  • 校准入口常驻，换手柄/换人时随时可调，不用进设置页
  • 不遮挡视频与遥测，驾驶中也能快速修正
  • 抽屉内容变长（已可滚动，影响可控）
  • 首次配置仍需用户理解「轴序号」概念
推荐度 ★★★★★
建议作为基础方案：所有设备都能用，且与现有交互一致。

方案 B · 首次使用弹出「校准向导」

选中「手柄」时，若该设备尚未校准，自动弹出 4 步向导：识别转向轴 → 确认方向 → 识别油门轴/死区 → 保存。之后可通过小齿轮重新打开。

  • 全引导流程，普通用户无需理解轴序号
  • 自动抓取变化最大的轴、自动测死区，一次到位
  • 可按手柄 id 记忆配置，插入新手柄再引导
  • 弹窗会遮住画面，驾驶中不宜弹出
  • 实现量比 A 大（步骤状态机 + 取消/回退）
推荐度 ★★★★☆
建议作为 A 的「一键校准」入口合并使用，而非独立方案。

方案 C · 选中手柄时切换为「手柄映射」面板

当输入源为「手柄」，抽屉把虚拟摇杆区域替换成该手柄的映射面板：轴监视器 + 实际输出 + 预设切换，专注调参。

  • 信息密度高，调轴时最直观
  • 不与其他输入源设置混在一起
  • 切回摇杆/键盘后入口消失，发现性差
  • 隐藏了虚拟摇杆，触屏用户可能仍想同时用
  • 与「输入源」切换语义重叠，容易困惑
推荐度 ★★★☆☆
可作为进阶视图保留，不建议作为唯一入口。

3 推荐落地方案（A + B 合并）

基础用 A：抽屉内嵌折叠卡（预设 + 轴选择 + 反向 + 死区 + 迷你轴监视）。首次连接新设备或点「一键校准」时用 B 的向导自动识别。数据与驱动参数一起持久化。

数据结构（前端 DriveParams 增加 gamepad 段）

interface GamepadConfig {
  version: 1;
  preset: 'xbox' | 'z-axis' | 'wheel' | 'custom';
  steering: { axis: number; invert: boolean;
              deadzone: number; max: number; center: number; };
  throttle: { axis: number; invert: boolean;
              deadzone: number; max: number; center: number; };
  padId?: string;   // 按手柄 id 记忆
}

映射公式（含中位偏移，兼容有漂移的轴）

// 去死区 + 中位校准 + 反向 + 上限
const d = (v, dz) =>
  Math.abs(v) < dz ? 0
  : Math.sign(v) * (Math.abs(v) - dz) / (1 - dz);

angle = clamp(
  d(axes[c.steering.axis] - c.steering.center, c.steering.deadzone)
  * (c.steering.invert ? -1 : 1) * c.steering.max);

throttle = clamp(
  d(axes[c.throttle.axis] - c.throttle.center, c.throttle.deadzone)
  * (c.throttle.invert ? -1 : 1) * c.throttle.max);

兼容性设计

轴序不一致

用 axis 索引配置而非固定偏移；pad.mapping === 'standard' 时给出推荐预设。

极性相反

每轴独立 invert；向导里用「是否与你预期一致」一步确认。

中位漂移 / 不自居中

保存 center 偏移；死区可调；极端设备可后续扩展 min/max 归一化。

多个手柄 / 热插拔

记录 gamepad index + id；断线回退到 0，连接检测常驻（现有逻辑保留）。

与 ESP32 手柄区分

浏览器 Gamepad 与车端 rc 通道是两条独立输入源，配置只作用于前者。

旧配置迁移

读取时深合并 DEFAULT，缺失 gamepad 段则补默认（steer=0 / throttle=1，等价现有行为）。

需要你确认的 3 个点（可直接用第 1 节的调试台验证）
  1. 你的转向到底在 axes[2] 还是别的索引？拨左拨右后看哪个轴在动。
  2. 左转对应 Z 的最小值还是最大值？决定要不要勾「反向」。（你的描述里这两句略有冲突）
  3. 是否还要把 W1–W5（或录制/模式切换）也映射到手柄按键？这会决定是否要一并做按钮配置。
