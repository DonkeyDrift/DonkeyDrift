## A. 立即行动(M4 收口,本周,便宜且解锁决策)

1. **补完 M4 验收链**——held-out 12 局 × 2 实例 × 3 seeds + 人驾基线 12 局。
   当前最大缺口:没有 held-out 门判定,连"该不该加预算"的决策都做不了。
2. **预算直接上 1M×3 seeds**——4-env 探针实测 1418 步/s 线性,1M ≈ **12 分钟**/seed;
   sdsandbox 终判"真杠杆 = 课程 + 堆里程";M4 同时加难课程(±1.8)与更严锚定
   (米制 2.0m 走廊),300k 明显吃紧(训练期 ep_len 仅 105~497 步)。
3. **`gain −8.114` 口径自查(条件触发)**——cte sim 单位→米制的换算系数要能一句话
   说清;验证法:中心线探针已知节点间距 × cte 读数对拍。若 gain 错,2.0m 走廊
   实际是别的宽度,D2 全部训练在错误通道里。**held-out 门大幅未达时优先查这个。**

## B. 训练效果(结构升级,M5 前半)

4. **观测增维(对"跑得稳"最直接)**——现 16 维 state 缺 yaw 与赛道进度:策略不知道
   车头朝向、看不到前方弯道。加 yaw + node 进度(或前方 N 节点曲率预览)→ 18~20 维。
   数据全齐:人驾 meta 有 rpy/pos,M4 driveline 工具链能补 pos→node;只差变换+重训。
5. **多 env PPO 训练**——1418 步/s 的 4-env 至今只当探针,训练仍单 env;on-policy
   多 env 还降低 batch 相关性。纪律:先 2 env(SubprocVecEnv 有 sdsandbox 死锁前科)
   → close(timeout) → 按端口清。
6. **速度项校准**——人驾 max 5.04 m/s,超速上限 8 m/s 从未被触碰(形同虚设);
   收紧到 ~6,或做"速度-曲率"引导(弯前减速),更贴近人的开法。
7. **模型选择纪律**——3 seeds × 各 gate 快照里挑 held-out 最优入 halloffame,
   不默认拿 final(EvalCallback 同路径覆盖丢过 1816 步模型的前科)。

## C. 真车落地(M5 双主线,两个结构性缺口)

8. **视觉轨是硬前置**——真车没有 cte/speed/gyro 遥测管线,16 维 state 策略**部署不了
   真车**。pixel-BC(240×320 降采样,sdsandbox 配方在案)→ pixel PPO 应为 M5 主线;
   web 采样器已在存图,数据零额外成本。
9. **sim-to-real 时序鲁棒**——纯 sync 0.05 训练 = 零抖动理想时序;sdsandbox 教训:
   真实时钟惩罚高增益策略(50ms 死时间比 20ms 难一个量级、抖动 p95 超边界 40%)。
   上车前必须加 action-jitter/delay 等价物做鲁棒性训练或验证,否则"sim 里稳、上车就飘"。
10. **真车控制频率定档**——0.05 vs 0.02 已拖两个里程碑,部署前必须定(决定训练档位)。
11. **实车物理层**——油门标定与 PWM 死区、电池压降致速度漂移(人驾 thr_mean 0.93
    全油门,速度一致性可疑)、相机曝光一致性、结构紧固。不属 RL 验收范围,但属
    "运行更稳定"的地基。
