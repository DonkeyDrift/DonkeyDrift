# Drive 全自动恒定输出：诊断与修复方案

## Context

`test-md-1.tflite`（本地训练）与 `deployed.tflite`（云端训练）在 Pilot Arena 中推理结果与验证集吻合，但 drive 页面切"全自动"后 pilot 的 steering/throttle 遥测基本恒定，小车冲出赛道。

静态分析已排除：模型输入形状（两者均为 `[1,120,160,3]`，二进制解码确认）、resize 口径（训练 `pipeline/training.py:100` 与车端 `PilotHolder` 同用 `fit_image_array`，320x240→160x120 同比例无白框；arena 的 `cv2.resize` 拉伸在 4:3 下等价）、解释器差异（车端与后端进程实测都在 `.venv`/TF 2.19.1，`get_model_by_type` 走同一 `KerasLinear+TfLite` 分支）、执行链（mode 门控/DriveMode/平滑器/ArdPWM 均标准；part 异常会停车而车在跑）。

剩余两个无法静态区分的根因，需要一次决定性实验：

- **H-A 帧冻结**：全自动时（推理+WebRTC 编码+60Hz 循环）pygame 相机线程饥饿，pilot 收到定格帧 → 恒定输出；视频流同时定格但用户注意力在车上不易察觉。
- **H-B 模型过拟合坍缩**：tub 为单会话 26 分钟数据（灰色无标记地面 + 鱼眼画面，`data/images` 实图确认无车道线），模型记住训练路线视角；实车姿态稍偏即 OOD，线性头输出坍缩到标签均值（小转向 + ~0.2 油门——与症状吻合）。Arena 每帧都来自训练分布，故"偏差很小"。

## Phase 1 — 诊断脚本（定位根因，~30 分钟）

新建 `tools/diagnose_pilot.py`（仓库根新目录），用 `.venv/bin/python` 运行，**运行前先停掉车端进程（相机独占）**：

1. **Test A（对照）**：按车端完全相同方式加载模型（`get_model_by_type('tflite_linear', cfg)` + `PilotHolder.load`），从 `data/images` 均匀抽 150 帧，走 arena 式预处理（PIL→RGB→缩放到 160x120）推理；输出 angle/throttle 的范围/标准差，与 catalog 标签算 MAE。预期：正常变化、MAE 小。
2. **Test B**：同批图像走 `PilotHolder.run()`（letterbox 路径），与 A 对比——确认车端预处理无差异。
3. **Test C（决定性）**：实例化 `Webcam(320,240,3)`（与车端同款），连续 30 秒逐帧 `PilotHolder.run()`，期间手持小车沿赛道移动；统计帧间隔、内容哈希去重数（帧是否新鲜）、输出范围/标准差，并落盘 3 帧样图供目检（方向/颜色/曝光）。

**判读**：
- C 帧新鲜但输出坍缩（angle std ≪ A）→ **H-B 成立**（模型/数据问题，非代码 bug）
- C 帧停滞/间隔异常（>500ms 或哈希重复）→ **H-A 成立**（相机管道问题）
- C 也正常 → 问题在运行时整车环境（负载/线程竞争），转入 Phase 1.5：给 `PilotHolder.run` 加环境变量开关的逐帧日志（输入 id/shape/mean + 输出），在终端手动起 `manage.py drive` 跑一次全自动看日志（注意 launcher 启动的车端 stdout 是 DEVNULL，须手动起）。

## Phase 2 — 修复（按诊断结果）

**无条件项（可观测性，两个分支都需要）** — `donkeycar/parts/pilot_holder.py`：
- 运行中每 ~5s 记一条 info 日志：输入 shape/dtype/mean + 最近输出值
- 帧冻结检测：pilot 运行中同一数组 id 且内容哈希连续 >2s 未变 → `logger.warning("模型输入帧疑似冻结")`

**若 H-A 成立** — 相机管道：
- `donkeycar/parts/camera.py` 为 `WEBCAM` 类型提供 OpenCV 实现路径（参照 `CSICamera.poll_camera` 的 `cv2.VideoCapture` + `cvtColor(BGR2RGB)` 模式，camera.py:253-257），cv2 阻塞读在 C 层释放 GIL，抗饿死；pygame 版保留为回退。`mycar/myconfig.py` 切换 `CAMERA_TYPE`。

**若 H-B 成立** — 非代码 bug，交付结论与数据改进指引（不改代码或仅小改）：
- 用彩色胶带标记赛道边界后再采集（当前地面无任何标记，模型只能靠货架/墙面记忆位置）
- 至少 3 个会话、含反向行驶与跑偏回正数据；可试 `TRAINING_IMAGE_SIZE=320x240`（鱼眼细节更多）或 categorical 模型
- 重训后先跑 Phase 1 的 Test C 作为"上路验收"，再实车验证

**顺带小修（卫生项）**：`web_ui/backend/routers/arena.py:283` 的 `cv2.resize` 拉伸改为 `fit_image_array`，与训练/车端口径统一（4:3 无影响，其他比例下防口径分裂；保持精确目标尺寸，不破坏原 XNNPack 修复）。

## Phase 3 — 验证

1. 重跑 `tools/diagnose_pilot.py`：A/B 一致、C 输出随场景变化
2. 实车：手动开上赛道 → 切全自动，TelemetryChart 的 pilot_angle 曲线在弯道应有摆动；PilotHolder 新日志显示输入统计在变化；小车完成 ≥3 圈不出轨
3. Arena 回归：预测结果与修复前一致
